# Go JS 1.6.6 Parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `tbc-contract-go` to npm `tbc-contract@1.6.6`, add TBC20 and TokenValidator, preserve old assets, and verify every in-scope path locally and on TBC testnet.

**Architecture:** The immutable npm 1.6.6 package generates deterministic public fixtures. Legacy token versions share one classifier; TBC20 and TokenValidator are separate focused packages; live transactions use the existing single-POST evidence collector.

**Tech Stack:** Go 1.17+, `tbc-lib-go`, embedded ASM/hex artifacts, Node.js fixture generation, Go test/race/vet, TBC testnet REST API.

**Spec:** `docs/superpowers/specs/2026-08-18-js-1.6.6-go-rust-sdk-parity-design.md`

## Global Constraints

- JavaScript authority is exactly npm `tbc-contract@1.6.6`; SDK runtime code must not invoke Node.js.
- Pool NFT v1 remains excluded.
- Default creation is NFT v2, FT v4, and StableCoin v4.
- NFT v0/v1, FT v1-v3, and legacy StableCoin outputs remain spendable.
- TBC20 is distinct from legacy FT.
- Live POSTs use only `https://api.tbcdev.org/api/tbc/`, one attempt per raw.
- WIFs, ephemeral keys, signatures, preimages, and unbroadcast raws never enter tracked files or logs.
