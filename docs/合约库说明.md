# tbc-contract-go 合约库说明

本仓库为 **TBC（TuringBitChain）链上合约与交易构造** 的 Go 语言实现，与 TypeScript 参考实现 **`tbc-contract`**（`lib/contract`、`lib/api`、`lib/util` 等）逐函数对齐，便于在服务端、CLI 或业务集成中以原生 Go 调用。

> 行为以已发布的 **`../tbc-contract/lib/...`** 与 **`../tbc-contract/docs/`** 为主要参考。Go 端通常复现 JS 的字节级输出（脚本、sighash 预映像、push 编码、手续费、找零）。

> 手工与场景级验证见 **`docs/test-cases/`**：每篇 **开头为参数定义（环境变量）**，随后为 **单文件可 `go run` 的最小示例**。

## 模块与依赖

- **Go module**：`github.com/LoongYearMeta/tbc-contract-go`
- **最低 Go 版本**：`1.17`
- **核心依赖**：
  - `github.com/LoongYearMeta/tbc-lib-go`：交易、脚本、签名、密钥与 UTXO 模型。**自包含**（已合并 `bec`、`crypto`、`bscript`、`partialsha256`、`wif` 等子包），不依赖 `libsv/go-bk` 或 `sCrypt-Inc/go-bt`。
  - `golang.org/x/crypto`：部分哈希/算法（如订单簿相关）。

## 目录结构（库代码）

## 包：`github.com/LoongYearMeta/tbc-contract-go/lib/contract`

单包 `contract`，逐文件对齐 TS `lib/contract/*.ts`。

### 同质化代币（FT）— `ft.go`

- **`FT`**：名称、符号、精度、总供应、`CodeScript` / `TapeScript`、合约 `txid` 等。
- **`NewFT(txidOrParams)`**：参数可为合约 `txid`（`string`）或新建参数 **`FtParams`**（`Name`、`Symbol`、`Amount`、`Decimal`）。
- **`(*FT).Initialize(*FtInfo)`**：用链上/索引拉取的元数据填充实例。
- **`MintFT`** / **`Transfer`** / **`TransferWithAdditionalInfo`** / **`BatchTransfer`** / **`MergeFT`**：与 TS 1.6.5 流程一致。附加信息转账会在最终 TBC 找零前插入零聪 `OP_FALSE OP_RETURN <data>` 输出。
- **FT v1-v3**：v1-v3 与 StableCoin 由 `util.ClassifyFTScript` 统一识别；新铸造使用已发布的 FT v3 模板（1884 字节代码、1856 字节 partial boundary）。
- **解锁脚本**：**`GetFTunlock`**、类型化 **`GetFTUnlockSwap`**，以及对应静态版本（外部已签名场景）；旧拼写保留为兼容包装。
- **构造交易**：所有交易经 `newFTTx()` 创建，**`tx.Version = 10`**（TBC 节点要求，`bt.NewTx()` 默认是 1）；外层调用方不应再用裸 `bt.NewTx()`。

### 稳定币（StableCoin）— `stablecoin.go`

- StableCoin 默认参与构建，owner 签名的转账、批量转账与合并路径可直接生成可广播交易。
- 管理员路径返回 **`*AdminPrepared`**。调用方需在外部完成 BIP327 / MuSig2 仪式，生成 64 字节 Schnorr 签名后回填 finalize；`tbc-lib-go` 不内置 MuSig2 聚合签名仪式。
- 2012 字节 StableCoin 脚本与 FT v1-v3 统一进入版本分类与 swap 解锁逻辑。

### NFT — `nft.go`

- **`NFT`**、**`NewNFT(contractID)`**、**`Initialize(*NFTInfo)`**。
- 集合与单枚元数据：**`CollectionData`**、**`NFTData`**，与 `nft.ts` 字段一致。
- 解锁脚本生成的 push 数据全部走 **`util.NftEncodeMinimalPushData`**，遵守 **`SCRIPT_VERIFY_MINIMALDATA`**。
- 不含旧版非线性 **`poolNFT` v1**；NFT 2.0 流动性池见下文 **`poolnft2.go`**。

### 订单簿（OrderBook）— `orderbook.go`

- **`OrderBook`**、**`NewOrderBook()`**。
- 支持已发布的 TBC-to-FT 卖单/买单构造、撤单、填签与撮合交易构建，保持 TS 字节布局。
- 未正式发布的双代币撮合扩展不属于本 SDK 的支持范围。
- 体量与边界条件复杂，建议结合 **`../tbc-contract/docs/orderBook.md`** 与 TS 参考实现理解。

### 多签 — `multisig.go`

- 地址与参数：**`GetMultiSigAddress`**、**`GetSignatureAndPublicKeyCount`**、**`VerifyMultiSigAddress`**。
- 与 JS **`MultiSig`** 一致的 TBC 转账、FT 转账等交易构造（返回结构如 **`MultiSigTxRawSendTBC`**、**`MultiSigTxRawTransferFT`**）。

### HTLC — `htlc.go`、`htlc_token.go`

- **`DeployHTLC`**、**`Withdraw`**、**`Refund`** 等；交易使用与 FT 一致的 **`newFTTx()`**。
- Token HTLC 提供部署、领取、退款的未签名+填签接口及直接私钥签名接口，FT 与 HTLC 状态在同一交易中原子变化。
- 解锁脚本中分支选择使用 **`OP_TRUE` / `OP_FALSE`** opcode token，避免 `bscript.NewFromASM` 对 `"0"` / `"1"` 这类奇数长度十六进制字符串报错。

### 存钱罐（定时锁 TBC）— `piggybank.go`

- **`GetPiggyBankCode`**、**`FreezeTBC`**、**`UnfreezeTBC`** 等与 `piggyBank.ts` 对齐；冻结手续费固定 80 sat/KB。

### Pool NFT 2.0 — `poolnft2.go`

- 仅实现 **Pool NFT 2.0（线性池）**，对应 `poolNFT2.0.ts`；旧版 pool NFT v1 故意未迁移。
- 池脚本模板由五份 **`//go:embed`** 文件提供，与 TS 1:1 对应：
  - `poolnft2_code.asm`（默认 pool 主体）
  - `poolnft2_ftlp_code.asm`（FT-LP 默认锁定脚本）
  - `poolnft2_ftlp_locktime_code.asm`（带 lock_time 的 FT-LP 锁定脚本）
  - `poolnft2_lock_code_pre.asm` + `poolnft2_lock_code_last.asm`（multisig 锁定 pool 主体）
- 普通与 lock-time FTLP 支持 FT v1-v3；FT v2/v3 使用 1884 字节代码和 1856 字节 partial boundary。
- 主要导出方法：
  - **`NewPoolNFT2(*PoolNFT2Config)`**、**`InitCreate(ftContractTxid)`**、**`InitFromContractID()`**
  - **`CreatePoolNFT(...)`**：常规建池
  - **`CreatePoolNFTWithLock(...)`**：multisig 锁定模式建池（参数包含 `pubKeyLock` 数组、`lpCostAddress`、`lpCostTBC`）
  - **`InitPoolNFT(...)`**：首次注入
  - **`IncreaseLP(...)`** / **`ConsumeLP(...)`**：增/减 LP；`ConsumeLP` 返回 **`[]string`**，with-lock-time 模式下为 `[unlockRaw, consumeRaw]`，否则为 `[consumeRaw]`，需按顺序广播
  - **`UnlockFTLP(...)`**：with-lock-time 模式下的 LP 解锁前置交易，返回 `(rawHex, error)`；当只有一笔已解锁 LP UTXO 时返回 `("", nil)`
  - **`SwapToToken(...)`** / **`SwapToTBC(...)`**：双向 swap；**`SwapToTBCLocal(...)`** 可直接使用调用方提供的 FT UTXO 与祖先数据，跳过 FT 输入发现
  - **`MergeFTLP(...)`**、**`MergeFTinPool(...)`**、**`BurnFTLP(...)`**
  - **`FetchFtLpUTXOList`** / **`FetchFtlpBalance`** / **`FetchFtlpLockTime`**
  - **`GetPoolNftTape(lpPlan, withLock, withLockTime)`**、**`GetPoolNftUnlockOffLine(...)`**
- TS 中已弃用的 **`initPoolNFTWithLockTime`**、**`increaseLpWithLockTime`**、**`consumeLpWithLockTime`** 故意未移植。

## 包：`github.com/LoongYearMeta/tbc-contract-go/lib/api`

对默认 **主网** `https://api.turingbitchain.io/api/tbc/` 与 **测试网** `https://api.tbcdev.org/api/tbc/` 发起请求；**`network`** 参数通常传 **`"mainnet"`**、**`"testnet"`** 或自定义以 **`/`** 结尾的 base URL。

- **GET 自动重试**：仅针对一组保守的瞬时网络错误（见 `api.go` 中 `isRetryableHTTPGetErr`）。
- **POST 不重试**：广播交易绝不重试，避免重复提交。
- **响应错误处理**：所有索引响应在 `json.Unmarshal` 后都会经过 `apiCodeError(body)`，捕获 200-with-non-200-code 信封。

常用导出函数：

- **链通用**：`GetTBCBalance`、`FetchUTXO`、`FetchUTXOWithAPITxID`、`FetchUTXOs`、`GetUTXOs`、`FetchTXRaw`、`FetchTXRawHex`、`BroadcastTXRaw`、`BroadcastTXsRaw`、`IsTxOnChain`、`FetchBlockHeaders`
- **FT**：`GetFTBalance`、`FetchFtUTXOList`、`FetchFtUTXO`、`FetchFtUTXOs`、`FetchFtUTXOsForPool`、`GetFtUTXOsMultiSig`、`FetchFtInfo`、`FetchFtPrePreTxData`
- **NFT**：`FetchNFTUTXO`、`FetchNFTUTXOs`、`FetchNFTInfo`、`FetchNFTs`
- **池子**：`FetchPoolNFTInfo`、`FetchPoolNFTUTXO`、`FetchFtLpBalance`、`FetchFtLpUTXO`
- **冻结 UTXO（存钱罐等）**：`FetchFrozenTBCBalance`、`FetchFrozenUTXOList`、`FetchUnfrozenUTXOList`、`FrozenToBTUTXO`
- **自定义脚本 UTXO**：`FetchUMTXO`、`FetchUMTXOs`、`GetUMTXOs`
- **稳定币**：`FetchCoinInfo`、`FetchCoinUTXOList`、`FetchCoinUTXOs` 等默认参与编译。

各响应结构体（如 **`FtInfo`**、**`NFTUTXO`**、**`PoolNFTInfo`**）定义于对应 `api_*.go`。

## 包：`github.com/LoongYearMeta/tbc-contract-go/lib/util`

与 TS `lib/util` 行为对齐，按文件划分：

- **`util.go`**：`FtUTXO`、`BuildUTXO`、`BuildFtPrePreTxData`、`ParseDecimalToBigInt`、`IsValidSHA256Hash`、`IsValidHexString`、`NFTInfo`、`NFTBrief`（这些类型放在 util 是为避免 `lib/api` ↔ `lib/contract` 的循环依赖）。
- **`ftunlock.go`**：FT 解锁所需的六个预映像辅助：`GetPreTxdata`、`GetPrePreTxdata`、`GetCurrentTxdata`、`GetCurrentInputsdata`、`GetContractTxdata`、`GetSize`。
- **`nftunlock.go`**：NFT 解锁辅助 + Go 端独有的 **`NftEncodeMinimalPushData`**。任何 NFT / coin NFT 解锁脚本的 push 数据都必须经此函数，不能直接调用 `bscript.AppendPushData`（后者对小整数不强制最小编码，会被链上 `SCRIPT_VERIFY_MINIMALDATA` 拒绝）。
- **`orderbookunlock.go`**：订单簿解锁所需预映像辅助。
- **`poolnftunlock.go`**：Pool NFT 2.0 预映像辅助（约 1100 行），包含 `getCurrentTxOutputsDataforPool2` 的逐 case 字节级移植（case 1 / 2 / 3-option1 / 3-option2 / 4），以及五个 `ServiceFeeAddress[1..5]` 服务费地址常量与 `IsServiceFeePkh`。
- **`utxoselect.go`**：`FindMinFiveSum` UTXO 选择辅助。

## 关键并行规约（必须遵守）

这些规约对应历史上已被发现并修复过的 bug，重写时极易复发：

- **`tx.Version = 10`**：所有合约交易都必须如此；`bt.NewTx()` 默认 1。统一走 `newFTTx()`（在 `ft.go`），不要再写裸 `bt.NewTx()`。
- **大小估算**：必须用 `(*bt.Tx).JSEstimateSize()`，**不要**用 `tx.Size()`。
- **手续费/找零调整**：普通路径使用 `tx.ChangeToAddress + JSEstimateSize`；大型自定义解锁路径按实现中的“两次签名、按真实字节调费、再次签名”流程收敛，不能在调费后复用旧签名。
- **设置顺序**：`tx.LockTime` 与每输入的 `SequenceNumber` 必须在调 `GetFTunlock` / `signP2PKHAtIdx` **之前** 设置，sighash 预映像会包含这两个字段。
- **`bt.UTXO.TxID` 是 forward（display-order）字节**：`hex.DecodeString(tx.TxID())` 直接得到正确字节，**不要**做 reverse。
- **`*big.Int → uint64`**：所有进入 `bt.Output.Satoshis`（或与 `utxo.Satoshis` 比较）的转换都走 `bigIntToSats(n, label)`。`n.Uint64()` 在溢出时静默截断。
- **Pool 的 `calculatePartialHash`** 必须调 `partialsha256.CalculatePartialHash`（JS 对齐的中间态哈希器），**不能**用普通 `crypto.Sha256` —— 否则建出的 pool 无法被花费。
- **Pool 的 `lpPlan` 优先级**：实例值 (`p.LpPlan`) 优先于调用方传入的 `lpPlan` 参数。
- **Pool 找零阈值**：`adjustFeeAndChange` 用 `size < 1000 ? 80 : ceil(size * 80 / 1000)`，且当找零 < **42 sat**（tbc-lib-js `Transaction.DUST_AMOUNT`，**不是** tbc-lib-go 的 `DustLimit = 1`）时整体丢弃。

## 在项目中引用

```go
import (
    "github.com/LoongYearMeta/tbc-contract-go/lib/api"
    "github.com/LoongYearMeta/tbc-contract-go/lib/contract"
    "github.com/LoongYearMeta/tbc-contract-go/lib/util"
)
```

典型流程：**`api.FetchUTXO` / `FetchFtUTXO`** 取得输入 → **`contract`** 中对应类型构造交易 → **`bec.PrivateKey` + `unlocker`** 填签名 → **`api.BroadcastTXRaw`** 广播。Pool NFT 2.0 with-lock-time 模式的 `ConsumeLP` 返回 `[]string`（最多两笔 raw），需按数组顺序逐笔广播：先 `unlockRaw` 上链，再 `consumeRaw`。
